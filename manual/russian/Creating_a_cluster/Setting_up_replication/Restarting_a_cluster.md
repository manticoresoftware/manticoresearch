# Перезапуск кластера

Если весь кластер репликации с несколькими узлами остановлен, первым нужно запустить один из них, чтобы остальные могли к нему присоединиться.

Исключение — кластер, в котором остался только один узел, например после выхода остальных с помощью `EXIT CLUSTER`. Если этот узел был остановлен штатно, его можно запустить обычным способом: Manticore восстановит кластер в состояниях `primary` / `synced` без `--new-cluster`.

Узел для первого запуска выбирают по файлу `grastate.dat` — небольшому файлу состояния репликации, который хранится в каталоге данных кластера. Наиболее важные поля:

- `seqno` — номер последней транзакции, известной этому узлу
- `safe_to_bootstrap` — признак того, что после штатной остановки кластера этот узел можно безопасно запустить первым

Пример содержимого `grastate.dat` после штатной остановки:

```text
# saved replication state
version: 2.1
uuid:    <cluster-uuid>
seqno:   12345
safe_to_bootstrap: 1
```

В этом примере:

- `seqno: 12345` означает, что этому узлу известны транзакции вплоть до порядкового номера 12345
- `safe_to_bootstrap: 1` означает, что этот узел помечен как безопасный для первого запуска

Если весь кластер был штатно остановлен, первым запустите узел, который был остановлен последним. На практике это обычно узел, у которого:

- наибольшее значение `seqno`
- установлено `safe_to_bootstrap: 1`

Сначала запустите этот узел. Manticore запустит кластер на основе его состояния. Затем обычным способом запустите остальные узлы, чтобы они могли присоединиться к кластеру.

Используйте этот способ после штатной остановки всего кластера.


<!-- intro -->
##### Командная строка:
Если вы запускаете Manticore напрямую, используйте:

<!-- request Bash -->

```bash
searchd --new-cluster
```

<!-- intro -->
##### systemd:
Если вы запускаете Manticore в Linux через systemd, используйте:

<!-- request Systemd -->

```bash
manticore_new_cluster
```
<!-- end -->

Если первым попытаться запустить узел без необходимого признака штатной остановки, Manticore отклонит запуск, чтобы не восстановить кластер из устаревшей копии.

### Если кластер аварийно остановился

Не считайте, что у последнего остановленного узла обязательно самые новые данные, и не запускайте кластер принудительно на произвольном узле. Сначала выполните инструкции из раздела [Восстановление кластера](../../Creating_a_cluster/Setting_up_replication/Cluster_recovery.md#All-nodes-crashed), чтобы определить правильный узел.
