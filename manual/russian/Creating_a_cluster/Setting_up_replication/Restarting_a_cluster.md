# Перезапуск кластера

Если весь многосерверный кластер репликации недоступен, сначала нужно запустить один узел, чтобы остальные узлы знали, к какой копии кластера присоединиться.

Есть одно исключение для обычного запуска: если кластер уже превратился в корректный одноузловой кластер, например после выхода остальных узлов с помощью `EXIT CLUSTER`, запустите оставшийся узел обычным способом. После корректного завершения работы Manticore восстанавливает такой кластер только с этим узлом в состоянии `primary` / `synced`, без `--new-cluster`.

Решение о первом запуске принимается на основе файла `grastate.dat` — небольшого файла состояния репликации, который хранится в каталоге данных кластера. Наиболее важные поля:

- `seqno` — номер последней транзакции, известной этому узлу
- `safe_to_bootstrap` — пометка, указывающая, можно ли безопасно первым запустить этот узел после корректного завершения работы

Пример содержимого `grastate.dat` после корректного завершения работы:

```text
# saved replication state
version: 2.1
uuid:    <cluster-uuid>
seqno:   12345
safe_to_bootstrap: 1
```

В этом примере:

- `seqno: 12345` означает, что этому узлу известны транзакции вплоть до порядкового номера 12345
- `safe_to_bootstrap: 1` означает, что этот узел помечен как безопасный для первого запуска

Если весь кластер был корректно выключен, запустите узел, который был остановлен последним. На практике это обычно узел со следующими признаками:

- самым большим значением `seqno`
- `safe_to_bootstrap: 1`

Сначала запустите этот узел. Это указывает Manticore запустить новую копию кластера на основе данного узла. Затем обычным способом запустите остальные узлы, чтобы они могли присоединиться к кластеру.

Используйте этот способ после корректного выключения всего кластера.


<!-- intro -->
##### Командная строка:
Если вы запускаете Manticore напрямую, используйте:

<!-- request Bash -->

```bash
searchd --new-cluster
```

<!-- intro -->
##### systemd:
Если вы запускаете Manticore в Linux через systemd, используйте:

<!-- request Systemd -->

```bash
manticore_new_cluster
```
<!-- end -->

Если сначала запустить другой узел без требуемого состояния после корректного завершения работы, запуск будет отклонён, чтобы защитить кластер от восстановления из устаревшей копии.

### Если работа кластера неожиданно прекратилась

Не предполагайте, что последний остановленный узел содержит самые новые данные, и не принуждайте к перезапуску произвольный узел. Сначала выполните инструкции из раздела [Восстановление кластера](../../Creating_a_cluster/Setting_up_replication/Cluster_recovery.md#All-nodes-crashed), чтобы определить правильный узел.
