# PURGE

`PURGE` удаляет выбранные данные, связанные с таблицей. Цель очистки указывает, что именно будет удалено.

```sql
PURGE <target> FROM TABLE <table_name>;
```

Сейчас поддерживается только цель `BULK_IMPORT`.

## PURGE BULK_IMPORT

```sql
PURGE BULK_IMPORT FROM TABLE products [OPTION clear_sessions=0|1];
```

`PURGE BULK_IMPORT` удаляет весь промежуточный корневой каталог, используемый [массовым импортом](../Data_creation_and_modification/Adding_documents_to_a_table/Adding_documents_to_a_real-time_table.md#Bulk-import), включая каталоги и файлы, оставшиеся после прерванной загрузки. Выполняйте эту команду только после того, как убедитесь, что для таблицы не выполняется загрузка напрямую на диск.

Если у таблицы есть открытый или завершившийся ошибкой пул [общего массового импорта по HTTP](../Data_creation_and_modification/Adding_documents_to_a_table/Adding_documents_to_a_real-time_table.md#Shared-HTTP-bulk-import), оператор будет отклонен. С `OPTION clear_sessions=1` он сначала отменяет этот пул: неопубликованные данные отбрасываются, запросы, которые все еще пишут в пул, получают ошибку, его индексаторы останавливаются, таблица освобождается для обычных записей, а затем удаляется корень промежуточного хранилища. Фрагменты, опубликованные ранее, остаются в таблице. Пока пул присоединяет свои фрагменты после коммита, оператор отклоняется; повторите его после завершения коммита. В Windows, пока запрос все еще пишет в пул, оператор может не удалить корень промежуточного хранилища сразу после отмены пула, потому что остановленные индексаторы еще некоторое время держат файлы открытыми; повторите его.

Открытый пул держит таблицу зарезервированной, поэтому обычные записи в нее и другие массовые импорты в нее завершаются ошибкой, даже если все его клиенты уже отключились; [`SHOW LOCKS`](../Securing_and_compacting_a_table/Freezing_and_locking_a_table.md#SHOW-LOCKS) показывает такую таблицу с типом блокировки `write_allow_readers`. Если клиенты остановились или аварийно завершились до коммита, это освобождает таблицу и отбрасывает подготовленные ими данные:

```sql
PURGE BULK_IMPORT FROM TABLE products OPTION clear_sessions=1;
```

Чтобы вместо этого опубликовать подготовленные документы, выполните коммит пула запросом без документов, как описано в разделе [общий массовый импорт по HTTP](../Data_creation_and_modification/Adding_documents_to_a_table/Adding_documents_to_a_real-time_table.md#Shared-HTTP-bulk-import).

`OPTION clear_sessions=1` не отменяет приватные сеансы массового импорта: приватный сеанс освобождает таблицу с помощью `SET bulk_import=0` или при закрытии соединения.

Оператор требует существующую локальную таблицу реального времени, которая не входит в кластер репликации. Он удаляет только промежуточное состояние записи напрямую на диск и не изменяет схему таблицы или проиндексированные документы. Если корень промежуточного хранилища отсутствует, оператор завершается успешно без каких-либо изменений. В режиме без конфигурационного файла `DROP TABLE` также удаляет корень промежуточного хранилища таблицы для записи напрямую на диск и отменяет ее общий пул.
